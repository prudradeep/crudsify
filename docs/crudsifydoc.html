Build a REST backend with CRUDSIFY

CRUDSIFY is an Express and Sequelize based REST API generator. It loads your Sequelize models, creates CRUD routes, applies validation, authorization, audit logging, soft delete behavior, custom policies, and optional Swagger documentation.

This documentation is served from the package at /crudsifydoc. Swagger for generated API contracts is available at /docs when enableSwagger is enabled.

Install and Initialize

Install CRUDSIFY in your Node.js backend project and run the CLI initializer.

npm install https://github.com/prudradeep/crudsify.git
# Windows
node_modules/.bin/crudsify-cli.cmd init

# macOS/Linux
node_modules/.bin/crudsify-cli init

The initializer copies starter folders and files such as config, models, migrations, seeders, and server entry points into your project.

Start the API server

node index.js

The server listens on SERVER_PORT from your environment file.

Configuration

CRUDSIFY reads its defaults from the package and merges your project config from config/index.js. To change a package setting, define the same key in your backend project's config/index.js. Environment secrets and database connection values belong in .env. 

module.exports = {
  service: "Inventory API",
  logQuery: true,
  enablePolicies: true,
  limit: 25,
  maxLimit: 100,
  maxEmbeds: 5,
  maxEmbedDepth: 2,
  dbPrimaryKey: {
    name: "id",
    type: "UUID",
    autoIncrement: false
  },
  enableCreatedBy: true,
  enableUpdatedBy: true,
  enableDeletedBy: true
};

Environment-Level Configuration

CRUDSIFY uses NODE_ENV as the Confidence criteria named env. Any package setting in your project's config/index.js can use $filter: "env" to return different values for development, uat, and production. Use $default for every environment that is not listed explicitly. 

// config/index.js in your backend project
module.exports = {
  logLevel: {
    $filter: "env",
    development: "debug",
    uat: "verbose",
    production: "error",
    $default: "info"
  },
  enableSwagger: {
    $filter: "env",
    production: false,
    $default: true
  },
  auditLogStorage: {
    $filter: "env",
    production: "database",
    $default: "file"
  },
  auditLogTTL: {
    $filter: "env",
    production: "60d",
    $default: "20d"
  },
  cors: {
    $filter: "env",
    production: {
      origin: ["https://app.example.com"],
      credentials: true
    },
    $default: false
  }
};

Database credentials are already environment-aware through .env: DB_DEV_* values are used for development, DB_UAT_* for uat, and DB_PROD_* for production.

Read Configuration Values

Use crudsify/config when custom APIs, policies, hooks, or utilities need to read the effective configuration after project overrides and environment filters are applied. 

const configStore = require("crudsify/config");
const authentication = configStore.get("/authentication");

// or
const { get } = require("crudsify/config");
const authentication = get("/authentication");

Models

Define Sequelize models in your project model directory. CRUDSIFY loads the models, applies helper fields, and generates routes for model names that do not contain an underscore. 

const { Model } = require("sequelize");
const _ = require("lodash");
const {
  getPrimaryKey,
  getTimestamps,
  getMetadata,
  getRecordScopes
} = require("crudsify/helpers/model");

module.exports = (sequelize, DataTypes) => {
  class Article extends Model {
    static associate(models) {
      Article.hasMany(models.comment);
    }
  }

  Article.init({
    ..._.cloneDeep(getPrimaryKey(DataTypes)),
    title: DataTypes.STRING,
    body: DataTypes.TEXT,
    status: DataTypes.STRING,
    ..._.cloneDeep(getRecordScopes(DataTypes)),
    ..._.cloneDeep(getTimestamps(DataTypes)),
    ..._.cloneDeep(getMetadata(DataTypes))
  }, {
    sequelize,
    modelName: "article"
  });

  return Article;
};

Server Options

The package export is called with an optional authentication strategy and an optional array of global Express middlewares. Global middlewares are mounted before CRUDSIFY registers generated endpoints. 

const crudsifyServer = require("crudsify");
const { refreshStrategy } = require("./strategies/refresh");

crudsifyServer(refreshStrategy, []);

Global Middleware Example

const rateLimit = require("express-rate-limit");
const crudsifyServer = require("crudsify");
const { refreshStrategy } = require("./strategies/refresh");

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 100,
  standardHeaders: "draft-7",
  legacyHeaders: false
});

crudsifyServer(refreshStrategy, [limiter]);

Models and Migrations CLI

CRUDSIFY model helpers should be used in both model files and migrations so generated endpoints, metadata, timestamps, primary keys, and record scopes stay aligned.

Generate a Model and Migration

Use the model command when you want CRUDSIFY to create both the Sequelize model file and its matching create-table migration. The command writes the model to models by default, or to the folder configured by modelPath. 

# Windows
node_modules/.bin/crudsify-cli.cmd model --name article --attributes title:string,body:text

# macOS/Linux
node_modules/.bin/crudsify-cli model --name article --attributes title:string,body:text

The command creates files like models/article.js and migrations/YYYYMMDDHHmmss-create-article.js. The migration table name is pluralized from --name, so article becomes articles.

Generate a Migration Only

Use the migration command when the model already exists or you only need a migration file. 

# Windows
node_modules/.bin/crudsify-cli.cmd migration --name article --attributes title:string,body:text

# macOS/Linux
node_modules/.bin/crudsify-cli migration --name article --attributes title:string,body:text

CLI Arguments

ArgumentRequiredDescription
--nameYesModel name used for the generated model class, model file, and migration table name.
--attributesYesComma-separated fields in field:type, field:array:type, or field:enum:{value,value} format.
--underscoredNoAdds underscored: true to the model and uses created_at/updated_at in the migration.
 
# Basic fields
node_modules/.bin/crudsify-cli model --name article --attributes title:string,body:text

# Array and enum fields
node_modules/.bin/crudsify-cli model --name article --attributes title:string,tags:array:string,status:enum:{draft,published}

# Underscored timestamps
node_modules/.bin/crudsify-cli model --name article --attributes title:string --underscored

Attribute types are passed through to Sequelize data types, so use names such as string, text, integer, boolean, date, json, array, and enum.

Query Parameters

List and find routes support query helpers for shaping results. Query defaults and limits are defined in your backend project's config/index.js, not in the request handler. 

// config/index.js in your backend project
module.exports = {
  limit: 20,              // default page size when $limit is not sent
  maxLimit: 100,          // largest accepted $limit value from a client
  maxEmbeds: 5,           // maximum number of $embed entries
  maxEmbedDepth: 2,       // maximum nested $embed depth, such as author.company
  allowParanoidQueries: false
};
ParameterRoutesConfigured byPurpose

$skipListRequest onlyNumber of records to skip for offset pagination.
$pageList$limit request value or limit defaultPage number for page-based pagination. Starts at 1.
$sortListModel readable/sortable fieldsSort by model fields. Prefix a field with - for descending sort.
$selectList, FindModel readable fieldsReturn only selected model fields.
$excludeListRequest onlyExclude records by id.
$countListRequest onlyReturn count information instead of a normal result set when supported by the handler.
$orListRequest onlyUse OR between field filters instead of the default AND behavior.
$embedList, FindmaxEmbeds, maxEmbedDepth in config/index.jsInclude associations. Valid values are association names from the Sequelize model.
$paranoidList, FindallowParanoidQueries in config/index.jsInclude soft-deleted rows only when the setting is enabled.
fieldNameListModel queryable fieldsFilter by a model field, for example ?status=active.
fieldNameOperListModel queryable fieldsChoose the filter operator for a field. Supported values include =, !=, <, <=, >, >=, between, notBetween, in, notIn, like, notLike, regexp, and notregexp.

Authentication

Authentication is enabled by default. Generated routes expect a bearer token in the Authorization header unless disabled globally or per route. 

Authorization: Bearer <jwt-token>

The default token strategy verifies JWTs with JWT_SECRET and JWT_ALGO. You can pass a custom auth middleware when starting CRUDSIFY.

const crudsify = require("crudsify");

const authStrategy = async (req, res, next) => {
  // Set req.auth = { isValid: true, credentials: { user, scope } }
  next();
};

crudsify(authStrategy);

authenticationtrueGlobally enable auth for generated endpoints.
jwt.secretJWT_SECRETSecret used to verify generated JWTs.
jwt.algoJWT_ALGOSupported HMAC algorithm.
saltRounds10Rounds used when generating password hashes.

Token Strategies

CRUDSIFY ships three authentication strategies for different token flows. Each strategy expects Authorization: Bearer <token> and sets req.auth.credentials.

StrategyImportToken typeBehavior
tokenStrategycrudsify/strategies/tokenaccessValidates access token, session id, session key, user status, and password-update requirement.
sessionStrategycrudsify/strategies/sessionaccessValidates access token and sends a fresh access token in X-Access-Token.
refreshStrategycrudsify/strategies/refreshrefreshValidates refresh token and sends fresh X-Access-Token and X-Refresh-Token headers.
 
const crudsifyServer = require("crudsify");
const { tokenStrategy } = require("./strategies/token");

crudsifyServer(tokenStrategy, []);

Sessions are single-login by default: creating a new session removes older sessions for the same user. If a user's stored password hash changes, existing sessions fail because the session stores the old password hash.

Authorization

CRUDSIFY can generate route scopes and record scopes for action-level and record-level authorization.

Route Scopes

When generateRouteScopes is true, CRUDSIFY creates scopes such as readArticle, createArticle, updateArticle, deleteArticle, recoverArticle, and association scopes.

Record Scopes

When enableRecordScopes is true, records can include a JSON field such as recordScope to control read, update, delete, recover, and association access.

module.exports = {
  authentication: true,
  generateRouteScopes: true,
  enableRecordScopes: true,
  recordScopeKey: "recordScope",
  authorizeRecordCreator: {
    root: false,
    read: true,
    update: true,
    delete: false,
    associate: false
  }
};

Scope Rules

Route scopes are compared with req.auth.credentials.scope. A scope prefixed with + is required, a scope prefixed with ! is forbidden, and normal scope values allow access when at least one is present. 

// User must have "manager", must not have "suspended", and may have "editor" or "owner".
scope: ["+manager", "!suspended", "editor", "owner"]

Custom Route Scopes

user.routeScopes = {
  rootScope: "Admin",
  readScope: "User",
  addUserGroupsScope: "Lead"
};

Generated scopes include root/action scopes such as readUser, createUser, updateUser, deleteUser, recoverUser, and association scopes such as addUserGroups, removeUserGroups, and getUserGroups.

Record Scope Example

article.recordScope = {
  root: ["Admin"],
  read: ["Writer", "Editor"],
  update: ["Editor"]
};

// A created record can store:

Permission State Semantics

IncludedPermission name is added to the user's scope.
ExcludedPermission is ignored.

Soft Delete, Recover, and Hard Delete

Soft delete is enabled when modelOptions.paranoid is true. Delete endpoints call Sequelize destroy behavior and recover endpoints restore soft-deleted rows.

  modelOptions: {
    timestamps: true,
    paranoid: true
  },
  enableRecoverEndpoint: true,
  allowHardDelete: false
};

If allowHardDelete is true, delete requests may include { "hardDelete": true }. Keep it disabled unless the route is protected for administrative users.

Model Extra Endpoints

Add extraEndpoints to a model when a custom route belongs naturally with that model. CRUDSIFY calls each function before generating the model's standard CRUD routes. 

const Joi = require("joi");
const { generateEndpoint } = require("crudsify/endpoints/generate");
const { updateHandler } = require("crudsify/handlers/create");
const { sendResponse } = require("crudsify/helpers/sendResponse");

article.extraEndpoints = [
  () => {
    generateEndpoint({
      method: "put",
      path: "/articles/:id/publish",
      summary: "Publish an article",
      tags: ["articles"],
      auth: true,
      scope: ["publishArticle", "Admin"],
      validate: {
        params: Joi.object({
          id: Joi.string().required()
        })
      },
      handler: async (req, res, next) => {
        try {
          const data = await updateHandler(article, {
            params: { id: req.params.id },
            body: { status: "published" }
          });
          sendResponse({ data, status: 200, res, next });
        } catch (err) {
          next(err);
        }
      },
      log: "Generating Publish Article endpoint."
    });
  }
];

Model hooks can customize generated behavior when handlers call hook points. Policies are preferred for request middleware behavior, while hooks are useful for model-specific data transformations.

Hooks

Model hooks let you preprocess a request or postprocess handler output without replacing CRUDSIFY's handlers. Set req.preHook or req.postHook to skip hooks for a manual handler call. 

article.hooks = {
  list: {
    pre: async (req) => req,
    post: async (req, docs) => docs
  },
  find: {
    pre: async (req) => req,
    post: async (req, doc) => doc
  },
  create: {
    pre: async (req) => {
      req.body.status = req.body.status || "draft";
      return req;
    },
    post: async (req, created) => created
  },
  update: {
    pre: async (req) => req,
    post: async (req, updated) => updated
  },
  delete: {
    pre: async (req, hardDelete) => {},
    post: async (req, hardDelete, deleted) => {}
  },
  recover: {
    pre: async (req) => {},
    post: async (req, recovered) => {}
  }
};

Error Handling

CRUDSIFY mounts errorResponder and handleNotFoundError after generated routes, Swagger, and documentation routes. Custom endpoints should call next(err) so the shared responder can format failures consistently.

Generated model routes initialize req.model at route entry. Custom routes that need model-aware error messages should pass the related Sequelize model as requestModel to generateEndpoint.

SequelizeValidationErrorReturns 428 Precondition Required with validation messages.
SequelizeUniqueConstraintErrorReturns 409 Conflict with duplicate field details.
SequelizeForeignKeyConstraintErrorReturns 422 Unprocessable Entity with a safer relationship message.
SequelizeDatabaseError or unknown errorsReturns 500 Internal Server Error with a generic message.
No matching routeReturns 404 Not Found with URL not found.

Backend Checklist

  1. Install CRUDSIFY and run crudsify-cli init.
  2. Fill .env with server, JWT, Swagger basic auth, and database values.
  3. Configure config/index.js for primary keys, paths, auth, audit logs, and validation.
  4. Create Sequelize models with CRUDSIFY helpers for primary key, timestamps, metadata, and record scopes.
  5. Add migrations and run them with Sequelize CLI.
  6. Set model routeOptions, routeScopes, policies, hooks, and associations as needed.
  7. Review built-in auth routes, token strategies, quick-start models, policies, and security constants if using quick-start.
  8. Use handlers, query helpers, response helper, and shared error handling for custom APIs.
  9. Start the server and inspect /crudsifydoc for package guidance.
  10. Open /docs to inspect the generated API contract when Swagger is enabled.
